How to triage the next report

  1. Read the report and preserve the original input, expected day and actual day.
  2. Resolve the tenant’s configured locale and form version; browser locale and intake tags are hints, not authority. If the tenant is unknown, investigate instead of merging.
  3. Distinguish the shared parser from the booking-v3 hint mismatch using the channel and form contract. Check anomalous symptoms rather than assuming every report in a bucket has been explained.
  4. Merge only when the mechanism matches an existing ticket. Equal subjects do not prove equal causes; different subjects do not prove different causes.
  5. Count each report ID once, link the appropriate issue, and check a fresh export before changing counts or closing either problem.
